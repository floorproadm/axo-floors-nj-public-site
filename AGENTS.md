# Architecture rules
- Serve /stairs from src/pages/Stairs.tsx through its dedicated SSR route and the existing legacy fallback, with page-scoped styling and inline asset-pointer galleries independent of Gallery data; keep metadata in the leaf route. Why: one canonical page preserves owner copy and existing forms, analytics, and other pages.
- Serve the owner-approved installation design from src/pages/Installation.tsx through the SSR /installation route and the legacy App fallback; keep wood diagrams and styling scoped, and keep /installation-v2 and /hardwood-flooring as HTTP 301 redirects to /installation. Why: one canonical page preserves owner edits and external links without duplicate content.
- Keep the /refinishing project photos as an inline horizontal scroll-snap strip using CDN asset pointers, isolated from Gallery data and routing and with no lightbox dialog; this preserves the existing gallery and SSR page.
- Keep Get Started journey transitions and branch validation in its feature module; the existing estimate server function revalidates and inserts through anonymous RLS, then notifies once after confirmed insertion, isolating other lead pathways.
- Derive Get Started services from the validated journey and normalize hidden answers before constructing label-rich notes on the same lead; retain the existing legacy estimate payload contract for isolated consumers.
- Keep project-photo previews memory-only and isolated from form payloads, using data URLs allowed by existing image-security rules; uploads remain disabled until private lead-scoped storage and staff access are verified, preventing accidental disclosure or orphaned attachments.
- Initialize GA4 in the root shell through a browser effect and a public server function exposing only the validated Measurement ID, so server-held configuration never leaks unrelated secrets.
- Observe the shared browser-history boundary for page measurement across existing routers; do not migrate rendering or edit form logic for analytics.
- Build page telemetry through the analytics privacy allowlist, using fixed titles, token-free paths, origin-only referrers and recognized campaign channels; never pass arbitrary URL values or document titles to Google.- Partial-estimate capture goes only through the server bridge in src/features/get-started/partial.* (HMAC-signed, HttpOnly session cookie, same-origin + throttled) and the canonical saveEstimate wraps the single lead insert with begin_finalization/complete; any bridge failure fails closed without blocking or repeating the lead save. Why: FloorPRO must never send a false abandonment alert and contact data must never reach the browser URL, logs or GA4.
- Server-render core marketing pages one at a time as dedicated TanStack routes that wrap the existing page in a react-router <Router> whose navigator does full page loads; head() owns title/canonical/JSON-LD, values must match the page's SEOHead props. Why: SSR for Google without migrating the legacy router or double-counting GA4.
- Keep /vinyl-plank-flooring hidden while the owner is off it: the URL answers 404 from src/routes/vinyl-plank-flooring.tsx via src/lib/vinyl-page-hidden.ts (never a redirect to another page), and the page stays out of every menu, the sitemap, robots and the App router, while src/pages/VinylPlankFlooring.tsx remains untouched in the repo. Why: the owner will resume this page, so its URL and source must not be reassigned. Restore by re-adding the App route, the menu entries and the sitemap path, then deleting the 404 route.
